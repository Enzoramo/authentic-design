# Design continuity and variation

Use for supplied earlier work, another concept, or authorized project design memory. This is not an automatic global tracking system.

- **Same product, new screen:** reuse identity and interaction rules. Different content may require a different layout without new branding.
- **Same brief, alternative concept:** change the organizing idea while preserving requirements; explain the tradeoff.
- **Independent product:** derive decisions anew. Do not inherit an old composition merely because it is convenient.

Use an existing project design document. Otherwise keep the record in the response unless saving project memory is authorized. Record only useful fields:

```text
Product / screen / date:
Audience, main task, and fixed constraints:
Evidence and assumptions:
Information structure and primary interaction:
Composition and density:
Type roles and color roles:
Imagery, geometry, motion, and voice:
Characteristic decision and why it belongs here:
Alternatives and tradeoffs:
Actual checks, artifacts, and unresolved issues:
```

This describes a design for comparison; it is neither an originality score nor a UI template. Keep it short and exclude private research transcripts or personal customer data.

Compare relevant authorized work. For independent products, distinguish justified shared conventions from unexamined habits. For a family of screens, consistency is positive evidence. Do not force divergence on every axis.

Without accessible history, disclose the limitation when it affects a claim. Do not claim comparison with unseen work, inspect unrelated projects, create a cross-client portfolio, publish project memory, or install a memory service just to increase variety.
